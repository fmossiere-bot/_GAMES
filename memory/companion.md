# AI Climate Companion — Architecture & Status

## Flow
```
User question
  → api-proxy.php
  → Fetch wiki-snippets.json from GitHub (234 pages, title + summary keywords)
  → LLM Retriever (Infomaniak Nemotron-30B) picks relevant page slugs
    → Fallback: keyword scorer if Infomaniak fails
  → Fetch full page content from GitHub raw
  → Claude answers (Haiku if wiki found, Opus if no wiki match)
  → Return: answer + source type + source badges
  → companion.php renders chat UI
```

## Models
| Role | Model | Cost |
|------|-------|------|
| Wiki page retriever | Infomaniak Nemotron-30B (`nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-FP8`) | €0.05/€0.20 per 1M |
| Wiki-grounded answer | Claude Haiku (`claude-haiku-4-5-20251001`) | ~$0.80/$4.00 per 1M |
| No-wiki fallback answer | Claude Opus (`claude-opus-4-7`) | ~$15/$75 per 1M |

## Infomaniak AI API
- Product ID: `109095`
- Endpoint: `https://api.infomaniak.com/2/ai/109095/openai/v1/chat/completions`
- Auth: Bearer token — env var `INFOMANIAK_API_KEY`
- Format: OpenAI-compatible
- Important: set `reasoning_effort: "none"` and `stream: false` to avoid thinking-mode output breaking JSON parsing

## Environment Variables (on server)
- `ANTHROPIC_API_KEY` — Claude API
- `INFOMANIAK_API_KEY` — Infomaniak AI (retriever)
- `GITHUB_TOKEN` — for wiki fetching (optional, increases rate limits)

## Source Attribution
Three answer modes, each with different UI badges:
- `wiki` — green badges showing page titles
- `ai` — orange "From AI knowledge" badge
- `hybrid` — green wiki badges + yellow "+ AI knowledge" badge

## Wiki Snippets Index
- File: `wiki/wiki-snippets.json` in GitHub repo
- Auto-generated by GitHub Action on every push to `wiki/**/*.md`
- Contains: slug, filename, label, summary (keywords from headings + bold text), category, tags
- api-proxy.php fetches this instead of index.md for retrieval
- Fallback: index.md parsing if snippets file unavailable

## System Prompt — Follow-up / Hybrid Behaviour (updated 2026-06-13)
The system prompt was strengthened to handle the case where a wiki page is found but the follow-up question asks for information beyond what the wiki covers:
- If the wiki has nothing NEW to add relative to prior turns, the model must supplement from training data rather than saying "nothing more is available"
- Explicit guidance for follow-up patterns ("anything else?", "what more?", "tell me more")
- Hard rule: never declare no information if training data has relevant knowledge
- Correct prefix: "From our knowledge base and AI:" when wiki was used earlier but has nothing new

## Key Design Decisions
- Retriever sees enriched label = title + summary + tags (NOT just title)
- `page_map` stores both `title` (clean, for display) and `label` (enriched, for retriever only)
- Further reading: disabled pending `### Further Reading` section implementation in wiki articles
- Source badges are non-clickable until wiki.the-uptake.com URL structure confirmed
- Inline links in answer text: orange, open new tab, blocked domains filtered (github, example.com, etc.)
- No hallucinated URLs: Claude forbidden from inventing URLs; LINKS marker removed from system prompt
